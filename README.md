# Kitsu — шаблоны интерфейса

Статические HTML/CSS/JS-шаблоны сайта Kitsu: **публичная часть** (`public/`) и **админка** (`admin/`). Это демонстрационный интерфейс: данные встроены в шаблон, запросов к API нет, выбранные настройки (палитра, тема, закладки, настройки профиля) сохраняются в браузере. Рабочий фронтенд живёт в другом репозитории; шаблоны — эталон композиции, поведения и токенов. Контекст и ловушки бэкенда — [PROJECT.md](PROJECT.md).

Смотреть онлайн: https://montihx.github.io/WebApp/

## Быстрый старт

```sh
npm ci
npm run dev        # Vite, корневая страница с выбором: сайт или админка
npm run check      # статические проверки public/ и admin/
npm test           # node --test tools/*.test.mjs
npm run build      # проверка манифестов и сборка в dist/
```

Страницы открываются и без сборки, прямо из каталога. Каталоги `public/` и `admin/` используют общий `tokens.css` в корне — сохраняйте эту структуру при размещении.

## Структура репозитория

| Путь | Что там |
|---|---|
| `index.html`, `favicon.svg`, `tokens.css` | Стартовая страница-навигатор, иконка, общие токены (цвета, шрифты, радиусы, отступы, длительности) |
| `public/` | Публичный сайт, 7 страниц, см. ниже |
| `admin/` | Админка v5, одна страница `index.html` и маршрутизация по `#/раздел/страница` |
| `tools/` | Сборка, манифесты, тесты (`*.test.mjs`), подмножество иконок Lucide, `visual-review.html`, `ui-audit/` |
| `docs/` | `ART_DIRECTION.md` (правила оформления), `BACKEND_PARITY.md` (журнал сверки с бэкендом), `screenshots/` (снимки экранов: `v3` — сайт, `v4` — админка) |
| `.claude/skills/kitsu-design/SKILL.md` | Короткие жёсткие правила владельца для агента |
| `.openai/hosting.json` | Настройка хостинга статического каталога `dist` |
| `MANIFEST.sha256`, `public/MANIFEST.sha256`, `admin/MANIFEST.sha256` | Контрольные суммы публикуемых файлов |
| `vite.config.js`, `package.json` | Dev-сервер и скрипты |
| `PROJECT.md` | Контекст проекта, бэкенд, целевой стек, чем шаблоны не являются |

Каталоги `dist/` и `node_modules/` в git не входят. Кэш Python (`__pycache__`, `*.pyc`) тоже игнорируется.

## Публичная часть

Семь страниц, общий `app.js` (шапка, поиск, закладки, диалоги, генеративные обложки) и по одному скрипту на страницу.

| Страница | Скрипт | Что показывает |
|---|---|---|
| `public/index.html` | `app.js`, `content.js`, `content-model.js` | Слайдер героя, продолжение просмотра, каталог, расписание релизов, обновления, сезон, коллекции |
| `public/anime.html` | `app.js` | Страница тайтла: метаданные, список пользователя, плеер (вкладки «Встроенный плеер» и «Плеер Kodik»), серии, связанные тайтлы, комментарии |
| `public/bookmarks.html` | `bookmarks.js` | Закладки по статусам, пустое состояние |
| `public/profile.html` | `profile.js` | Свой профиль, пустое состояние |
| `public/profile-settings.html` | `profile-settings.js` | Настройки: профиль, аккаунт, пароль, уведомления |
| `public/user.html` | `user.js` | Чужой профиль, состояние «не найден» |
| `public/auth.html` | `auth.js` | Вход и регистрация |

Файлы: `public/fonts/` — локальные шрифты (Dela Gothic One, Onest, JetBrains Mono), `public/vendor/` — Lucide с лицензией, `public/img/` — арт страницы входа в двух палитрах.

Поведение, на которое опираются тесты: слайдер на девять секунд и единственная полоса прогресса; стрелки только шире 720 px, на телефоне свайпы; клавиатура и reduced-motion сохраняются; если постер не загрузился, вместо него рисуется генеративная обложка (`paintImageArt` в `public/app.js`). Подробнее — `public/README.md`.

## Админка

Один каркас `admin/index.html`, данные в `data.js`, контракты запросов в `contracts.js`, экраны и рендереры в `app.js`. Семь разделов: Пульт, Каталог, Очереди, Парсер, Стенд, Люди, Настройки. Запросы не отправляются: кнопка с последствиями показывает точный запрос из `contracts.js` и честно сообщает, что это макет. Время из API — наивный UTC, показывается в Asia/Almaty. Карта разделов, все запросы и находки в бэкенде — [admin/docs/HANDOFF.md](admin/docs/HANDOFF.md).

## Слои CSS и токены

- `tokens.css` — единственный источник значений: `--fs-*`, `--radius-*`, `--space-*`, `--dur-*`, `--ease-*`, цвета палитр. Новые значения добавляются сюда, существующие токены не переименовываются.
- `public/styles.css` — основа: компоненты, темы, адаптив.
- `public/kitsu-v3.css` — слой оформления v3, подключается после основы; правила в нём усиливаются префиксом `:root`.
- `admin/styles.css` — оформление админки поверх `tokens.css`.

Правило «одна функция — один компонент»: одинаковые по назначению элементы определяются один раз, без копий в другом слое. Палитры «Сакура» (по умолчанию) и «Обсидиан», тёмная и светлая темы; выбор хранится в `localStorage["kitsu-palette"]` и `html[data-palette]`.

## Сброс кэша

Стили и скрипты подключаются с версией в адресе. Сайт: `?v=v3-NN` в `public/*.html`, корневом `index.html` и тестах `tools/controls.test.mjs`, `tools/quiet-ui.test.mjs`. Админка: `?v=v5-N` в `admin/index.html` и в тех же двух тестах. При изменении CSS/JS поднимайте номер одной заменой по всем файлам, иначе тесты упадут.

## Проверки и тесты

- `npm run check` — `public/tools/qa.mjs` и `admin/tools/qa.mjs`: наличие обязательных токенов и селекторов, контраст по палитрам, структура страниц; результат пишется в `qa-results.json`.
- `npm test` — тесты на `node:test`: админка (`admin.test.mjs`), закладки, согласованность стилей и разметки (`consistency`), паритет контента (`content-parity`), размеры управляющих элементов (`controls`), слайдер героя, «тихий» интерфейс (`quiet-ui`), имена тайтлов, манифесты.
- `npm run check:integrity` — только проверка манифестов.

Если проверка требует селектор, которого больше нет в стилях, удаляйте его из списка проверки вместе с правилом, а не возвращайте мёртвый код.

## Сборка и манифесты

`npm run build` (`tools/build.mjs`) проверяет манифесты до изменения `dist/` и копирует только публикуемые файлы. Сборка прекращается при неучтённом файле, пропавшем файле или несовпадении суммы; проверки ничего не перезаписывают. Список файлов общий — `tools/publish-files.mjs`; в сборку не входят `docs`, `tools`, `screenshots`, файлы `.md`, `.sha256` и QA-отчёты. Символические ссылки не поддерживаются.

После намеренного изменения ресурсов:

```sh
npm run manifest:update
npm run check:integrity
npm test
npm run build
```

`manifest:update` обновляет хеши и добавляет новые файлы; пропавшие файлы из списков не удаляются — строку убирайте вручную. Изменённые ресурсы, отчёты и манифесты коммитятся вместе.

`tools/lucide-subset.mjs` собирает урезанный `lucide.min.js` из `tools/vendor/lucide-*.full.js`; запускайте после добавления иконки.

## UI-аудит

`tools/ui-audit/run.sh` поднимает локальный сервер и прогоняет скрипты на Playwright (нужен Python с Playwright): `iconaudit` и `iconaudit2` (иконки без рамок), `pillaudit` (без круглых форм), `hoveraudit` (наведение), `emojiaudit` (без эмодзи), `layoutaudit` (вёрстка на 320–1920 px без переполнений), `contrastaudit` (контраст), `admin_routes.py` (маршруты админки). Правила — `.claude/skills/kitsu-design/SKILL.md`. `tools/visual-review.html` — страница для просмотра ширин 375, 390, 768 и 1440 px через iframe; в сборку не входит.

## Порядок работы над изменением

1. Правка в нужном слое CSS/JS, расположение блоков не меняется.
2. Поднять версию кэша (см. выше).
3. `npm run manifest:update`, `npm test`, `npm run check`, `npm run build`.
4. Запись в `docs/BACKEND_PARITY.md` (одна строка на изменение, свежие — сверху блока).
5. PR с таблицей «было → стало».
