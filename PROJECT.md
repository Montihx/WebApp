# Kitsu — контекст проекта для шаблонов

## Что это за репозиторий

Здесь живут HTML-шаблоны интерфейса для сайта Kitsu: административная
панель и публичная часть. Шаблоны доводятся до готовности ЗДЕСЬ, в
изоляции, без сборки и без сети. Перенос в рабочий проект — отдельная
задача, отдельным агентом, позже.

Смотреть можно по ссылке: https://montihx.github.io/WebApp/

Два шаблона парные, у них общая дизайн-система:

- `admin/` — админка, 20 экранов, диалоги, ящики, палитра команд,
  две темы;
- `public/` — публичный сайт, две страницы: главная и страница тайтла
  с плеером.

## Что такое сам Kitsu

Сайт для просмотра аниме. Владелец один, он же единственный
пользователь на сегодня: сейчас всё крутится на домашнем стенде,
внешнего трафика нет. Проект готовится к переезду на VPS и открытию для
людей — поэтому решения принимаются так, как будто пользователи уже
есть.

Каталог наполняется автоматически из двух внешних источников:

- **Kodik** — список аниме и ссылки на видеоплеер. Главный источник
  записей. Метаданные у него грубые: свои теги вместо жанров, названия с
  техническими метками вроде `[ТВ-2]`.
- **Shikimori** — постеры, описания, жанры, студии, даты выхода,
  оценки. Обогащает то, что пришло из Kodik. Жёсткий лимит: **1 запрос в
  секунду**, и это ограничение определяет сроки всех массовых операций.

Каталог на момент написания — около 5661 тайтла.

## Как устроен бэкенд

- **Go** (chi + pgx, без ORM) — основная часть API. Порт с Python идёт
  по схеме strangler fig и почти завершён.
- **FastAPI** — остатки, которые ещё не портированы. Для фронта разницы
  нет, пути одинаковые.
- **PostgreSQL** — данные. **Redis** — кэш и очередь.
- **asynq** — фоновые задачи (парсеры). Очередь `parsers` работает с
  конкурентностью 1: одновременно выполняется ровно одна задача парсера.
- **nginx** — маршрутизация. **Docker Compose** — всё окружение.

Базовый префикс API: `/api/v1`. Авторизация — JWT в заголовке
`Authorization: Bearer`. Большинство админских ручек требуют
`is_superuser`, очередь комментариев — роль модератора.

## Ловушки бэкенда, которые обязан знать любой, кто делает фронт

**1. Время приходит без обозначения зоны.** Бэкенд отдаёт наивный UTC:
`"2026-08-12T14:38:00"`, без `Z`. Это сделано намеренно, ради
совместимости с прежней питоновской сериализацией, и менять это нельзя —
сломается побайтовая сверка эталонных фикстур.

Если написать `new Date("2026-08-12T14:38:00")`, браузер поймёт строку
как местное время, и все длительности уедут на величину часового пояса.
У владельца это +5 часов: задача, идущая 6 минут, показывается как
идущая 5 часов 6 минут.

Правило: одна утилита разбора на весь проект, дописывающая `Z`, и
никаких вызовов `new Date()` на строке из API напрямую.

**2. Наличие поля в ответе не значит, что его можно записать.** Пример:
`year` у аниме вычисляется из `aired_on` и не является колонкой.

**3. Наличие сохранённой настройки не значит, что рантайм её читает.**
Настройки парсера хранятся, но потребляет ли их воркер — отдельный
вопрос.

**4. Полная синхронизация Kodik не публикует промежуточный прогресс.**
Счётчики и процент пишутся один раз, в конце. Тридцать минут поле
`progress` равно нулю — это не поломка, это устройство. Живой прогресс
есть только у задачи обновления связей Shikimori.

**5. Многое просто отсутствует, и придумывать это нельзя.** Нет отметки
уведомления прочитанным. Нет восстановления из бэкапа. Нет истории
мониторинга, только один снимок. Нет CRUD ролей. Нет фильтров и общего
счётчика в журнале аудита. Полный список — в
`admin/docs/FUNCTIONAL_COVERAGE.md`, там же колонка «Чего не
показывать».

## Целевой стек

Шаблоны переносятся в Next.js-проект со следующим стеком (решение
принято, обсуждению не подлежит без явного пересмотра):

| Слой | Решение |
| --- | --- |
| Каркас | Next.js App Router + React 19 + TypeScript strict |
| Стили | Tailwind 4, CSS-first токены |
| Компоненты | shadcn/ui поверх Radix, единый пакет `radix-ui` |
| Публичные данные | Server Components + прямой `fetch` |
| Данные админки | TanStack Query v5 |
| Состояние в URL | nuqs — фильтры, поиск, сортировка, страницы |
| Глобальное состояние | Zustand — только тема и настройки плеера |
| Формы | React Hook Form + Zod |
| Анимация | `motion` (бывший framer-motion). GSAP не использовать |
| Плеер | Vidstack поверх hls.js |
| Иконки | lucide-react |
| Тосты | Sonner |
| Графики | Recharts |
| Даты | date-fns + `@date-fns/tz`, одна разрешённая утилита |
| Проверки | Playwright + `tsc` + сборка Next |
| Линтер | Biome |
| Пакеты | pnpm |

Три архитектурных правила важнее списка библиотек:

1. **Серверные компоненты по умолчанию.** `'use client'` ставится на
   конкретную кнопку или виджет, не на страницу целиком.
2. **Одна утилита времени**, см. ловушку №1 выше.
3. **Ошибка обязана быть видна.** Никаких `catch { return [] }` —
   упавший запрос не должен выглядеть как честная пустота. На каждый
   сегмент маршрута свои `loading.tsx` и `error.tsx`.

## Чем эти шаблоны НЕ являются

- Это **не рабочий фронтенд**. Ноль вызовов `fetch`, ноль обращений к
  `/api/v1`. Все данные захардкожены.
- Цифры в шаблонах — **примеры**. 24 812 пользователей, 18 429 релизов,
  12 на модерации — это заполнитель, реальные значения другие. Приводить
  их «в соответствие» не нужно.
- Это **не код для вставки**. Vanilla JS и обычный CSS — эталон
  композиции, поведения и токенов. При переносе CSS пересобирается
  токенами Tailwind и компонентами shadcn, один в один не переезжает.

## Правило проверки, действующее для всех

Не доверять этим шаблонам, их документации, старому фронтенду и
OpenAPI без повторной проверки по актуальному коду бэкенда. Если код
расходится с документом — приоритет у кода: остановиться, записать
расхождение, и только потом менять интерфейс.

Это правило работает в обе стороны: если считаешь, что задача
сформулирована неверно — останавливайся и пиши с обоснованием, а не
обходи молча.
